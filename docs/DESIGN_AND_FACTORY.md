# Design and factory

The page **Design and factory** (group Services) shows the reports that the design tools (EH3D-PHOENIX-PCB) left as JSON files in a project of the store (applications `pcb`, `cam`, `laser`, `pnp`, `cad`). Code: `src/pages/FactoryPage.tsx` and `src/services/design.ts`.

A JSON file is a report if it has the shape of the output of `phoenix check` / `connectivity` (rule findings, confirmed and inconclusive), `bom` (the bill, with offers and totals), the assembly bill, the manifest of `fabpack` or the summary of `panel`. The page reads at most twelve small JSON files of the project and shows each as tables. Severity is said in words and in a mark as well as in a colour; a finding can be followed by its object, and its position (in millimetres) copied.

**Running the checks.** An operator (with the scopes `jobs:prepare` and `projects:write` for a token) picks a project of the `pcb` application and a board file of it and presses one of the four buttons (check, bill of materials, fabrication package, panel). Studio sends `POST /api/v1/apps/pcb/jobs`, reads the job every second until it ends and reads the project again: the report is the file `reports/<kind>.json`, an envelope with the JSON the program wrote (`report`), its exit code and its error output. A server that is not set up to run the design program answers `501 design_run_unavailable` and the page says so; the run is off on the server by default (`design_run` in the security page and `design_program` in `server.cfg`). The dry run of the fabrication package keeps only text, which is not a report. See `DESIGN_FACTORY_CONTRACT_NEEDS.md`.
